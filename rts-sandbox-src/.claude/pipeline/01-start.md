  ЧАСТЬ 0. ЧТО У ТЕБЯ НА РУКАХ
================================================================================

Три отдельные вещи. Разделены намеренно: шаблон Unity ты меняешь под себя,
пайплайн обновляется независимо от него.

  1) unity-template.zip          — твой шаблон Unity-проекта
     Минимальный проект без Library. Внутри:
       ProjectSettings/ProjectVersion.txt      пин версии Unity
       Packages/manifest.json                  список пакетов
       Packages/packages-lock.json             ОБЯЗАТЕЛЬНО — пин версий пакетов
       ProjectSettings/EditorSettings.asset    Force Text + Visible Meta Files
       Assets/_Project/{Scripts,Scenes,Prefabs,Art,Audio,Configs}/  скелет папок
       Assets/_Project/Scenes/Main.unity       одна пустая сцена в Build Settings
     Пакеты докачаются при первом открытии в Unity. .git внутри НЕТ.
     Файлов .gitignore / .gitattributes / .editorconfig тут НЕТ — их ставит
     install.js, чтобы они жили в одном месте и обновлялись вместе с пайплайном.
     Как собрать этот шаблон с нуля — Приложение А, 08-unity-template.md.

  2) gamedev-pipeline.zip        — сам пайплайн
     Внутри:
       CLAUDE.md                  правила, всегда в контексте Claude Code
       .claude/                   всё хозяйство пайплайна (структура — Часть 1)
       install.js                 установщик, запускается вне Claude Code
     Обновляется отдельно от шаблона. Умеет доставиться в проект, который
     уже в работе, не тронув твои доки и задачи.

  3) README-first-run.txt        — шпаргалка на 10 строк
     Порядок первого запуска, чтобы не держать в голове.


--------------------------------------------------------------------------------
  Первый запуск, по шагам
--------------------------------------------------------------------------------

  1. Распаковал gamedev-pipeline.zip куда угодно, положил рядом с install.js
     свой unity-template.zip. Оттуда в PowerShell:

       node install.js C:\Games\NeonWave

     Папку создавать заранее не надо, распаковывать шаблон руками тоже.
     Установщик сам разберётся, что делать, по тому, что лежит в папке:

       папки нет или пустая        распакует шаблон Unity, поставит пайплайн
       проект Unity, кода нет      шаблон уже распакован — просто пайплайн
       проект Unity со своим кодом поставит пайплайн, доки потом соберёт /adopt
       уже есть .claude           обновит пайплайн, доки и задачи не тронет

     Он печатает выбранный режим и ПОЧЕМУ его выбрал. Не согласен — есть
     флаги --new, --adopt, --update, но нужны они редко.

     Что сделал установщик:
       - распаковал шаблон, если было нужно, развернув лишнюю вложенную
         папку, если её наделал архиватор
       - разложил CLAUDE.md и .claude/ по местам
       - положил качественный .gitignore и .gitattributes под Unity
         и .editorconfig
       - git init, ветка main, первый коммит "template"
       - записал .claude/PIPELINE_VERSION
       - напечатал: что дальше делать

  3. Открыл проект в Unity один раз — пусть докачает пакеты и соберёт Library.
  4. Проверил, что MCP for Unity подключен и отвечает.

Всё. Дальше пайплайн живёт внутри проекта и едет вместе с ним в git.
Про остальные режимы install.js и версии — ЧАСТЬ 10, 07-operations.md.

--------------------------------------------------------------------------------
  Источники истины — кто главный при расхождении
--------------------------------------------------------------------------------

  что задумано ........... docs/            (после апрува, status: accepted)
  что ты хочешь .......... concept/         (пока не перенесено в docs)
  что сделано ............ tasks/ + tasks/done/
  что реально в коде ..... код              (главнее доков по факту)
  почему так решили ...... файл задачи

  Правило: доки описывают замысел, код описывает факт. Разошлись — ИИ
  обязан показать расхождение и спросить, а не выбрать удобное молча.


--------------------------------------------------------------------------------
  Роли
--------------------------------------------------------------------------------

  ТЫ:   геймдизайн и все решения, приёмка, плейтест, приоритеты,
        ассеты (модели, звуки), правки в Unity Editor руками.
        Код не пишешь.

  ИИ:   код, диагностика багов, дешёвая проверка (компиляция, консоль),
        документация, ведение задач, черновики дизайна ПО ЗАПРОСУ.

  ИИ НЕ ДЕЛАЕТ никогда: не принимает дизайн-решения молча, не правит
  принятые доки без спроса, не объявляет задачу готовой без твоего плейтеста,
  не расширяет скоуп текущей версии сам.

  Дизайн можно делегировать: просишь продумать баланс или уровень — ИИ пишет
  в доку со status: proposed. В работу это не берётся, пока ты не подтвердил
  и статус не стал accepted. Один механизм на оба случая.

--------------------------------------------------------------------------------
  ШАГ 2. Запускаешь Claude Code, пишешь /intake
--------------------------------------------------------------------------------

ИИ читает всё необработанное в concept/, грузит скилл concept-intake.
Спрашивает сразу, батчем, каждый вопрос с вариантами и рекомендацией:

  Разобрал первую-идею.md. Шесть вопросов, по каждому мой вариант:

  1. Управление стрельбой: автоогонь в сторону движения / отдельное
     прицеливание второй рукой (twin-stick) / стрельба по кнопке в сторону
     взгляда. Рекомендую twin-stick — уклоняться и стрелять одновременно
     интереснее, чем стрелять туда, куда летишь.
  2. Арена: замкнутая с границами / зацикленная / скроллящаяся.
     Рекомендую замкнутую — проще и читаемее.
  3. Смерть с одного попадания или есть здоровье? Рекомендую 3 хита:
     одно попадание в аркаде без обучения фрустрирует.
  4. Апгрейды между волнами — пока не задизайнены. Сколько их всего
     нужно на MVP? Рекомендую 6, чтобы выбор из трёх не повторялся.
  5. Счёт: только за убийства / за убийства и время / множитель за серию.
     Рекомендую множитель — он и есть причина рисковать.
  6. Рекорд сохраняем локально между запусками?

Отвечаешь как удобно, свободным текстом:

  1 - twin-stick да. 2 - замкнутая. 3 - 3 хита. 4 - апгрейды потом,
  сначала хочу чтобы стрельба ощущалась. 5 - множитель за серию. 6 - да

Ключевое: «потом» по пункту 4 — это команда отложить. Вопрос уезжает
в очередь, ИИ не спрашивает про апгрейды до /ask и не выдумывает их сам.

Что ИИ делает дальше:

  - Пишет доки, сам решая, что куда:
      docs/00-vision.md          жанр, ощущение, референс
      docs/01-core-loop.md       петля: волна -> бой -> награда -> волна
      docs/03-ux-ui.md           экраны: титул, игра, смерть
      docs/04-tech-design.md     стек, структура, как устроен вход в игру
      docs/05-scope.md           что в MVP, что за бортом
      docs/mechanics/M-001-movement.md    status: accepted
      docs/mechanics/M-002-shooting.md    status: accepted
      docs/mechanics/M-003-enemy-waves.md status: accepted
      docs/mechanics/M-004-upgrades.md    status: proposed, пусто, отложено
      docs/06-open-questions.md  Q-1 апгрейды — отложен тобой
      docs/CHANGELOG.md          создано из concept/первая-идея.md
  - Отдельный файл получает только самостоятельная система, про которую
    можно написать «как она работает». Деталь внутри системы — правка
    в её доку, а не новый файл.
  - Набор общих доков ИИ определяет сам под проект. В аркаде понадобился
    кор-луп, в пазле он может быть не нужен, а нарративной игре нужны
    доки, которых в этом примере нет. Заводится то, про что есть что
    сказать, а не список по шаблону.
  - Заполняет шапку CLAUDE.md: название, жанр, платформы, стек.
  - Переносит concept/первая-идея.md в concept/processed/
  - Говорит: доки готовы, 1 вопрос в очереди, дальше /plan

ВАЖНО: обработанные файлы в processed/ заморожены. Хочешь дополнить —
новый файл в concept/, даже если это одна строка. ИИ в старые не смотрит.
