Ты берёшь задачу в работу. Правила ролей, апрувов и проверки — в CLAUDE.md,
здесь только порядок действий.

## 1. Состояние — одной командой

    node .claude/scripts/board.js --brief

Больше ничего пока не читай. Если в выводе есть строка `АВАРИЙНО: in-progress` —
это не /next, это обрыв прошлой сессии: скажи об этом и предложи `/resume`.
Если есть строка `ФОРМАТ БИТ` — сначала `--validate` и починить.

## 2. Какая задача

Берёшь ту, что в `STATE: задача`. Если там пусто — первая `todo` в списке
текущей версии по порядку из файла milestone. Скажи одной строкой, какую взял;
апрува не жди.

Не бери и объясни, что делать вместо:
- `needs-design` — нужно решение пользователя. Предложи `/ask` и возьми следующую.
- `blocked` — назови, чего ждёт (`blocked-by`), и возьми следующую.
- `review` — она уже сделана и ждёт ЕГО плейтеста, а не твоей работы.
- родитель с подзадачами — в работу идёт подзадача, не он.

## 3. Что прочитать

- файл задачи целиком;
- доки из её поля `mechanics` — по ID, не папкой;
- `.claude/project-map.md` — только если задача трогает код, которого ты
  в этой сессии не видел.

Дока механики в `proposed` — стоп: замысел не подтверждён, работать нельзя.

## 4. Чекпоинт — сам, без спроса

    node -e "console.log(new Date().toISOString().slice(0,10))"
    git add -A
    git commit -m "cp(T-XXX): before <краткое что>"
    git rev-parse --short HEAD

Дерево было грязным — значит в чекпоинт попали и правки пользователя в Unity;
так и надо, это фиксация состояния ДО твоей работы. Скажи об этом одной строкой.

Короткий хеш запиши в `checkpoint` файла задачи и в `.claude/state.md`.

## 5. Открой задачу

В front-matter: `status: in-progress`, `updated:` сегодняшняя дата.
В `.claude/state.md` три строки: задача, следующий шаг, хеш чекпоинта.

## 6. Загрузи скилл под тип работы

    механика геймплея, движение, стрельба, враги, физика   gameplay-mechanic
    экраны, меню, HUD, титульный экран, навигация          ui-flow
    сохранения, настройки, профиль                         save-and-settings
    уровни, конфиги, ScriptableObject-ы, баланс            content-and-balance
    звук, VFX, тряска камеры, game feel                    feedback-polish
    баг                                                    bugfix

И дополнительно `unity-asset-safety`, если будешь трогать префабы, сцены,
материалы или сериализованные поля — то есть почти всегда.

Ни один не подходит — работай без скилла и скажи об этом: возможно,
эта работа повторяется и её пора оформить через `/new-skill`.

## 7. План

Подробный план — в раздел `План` файла задачи. Обязательно, до начала работы.

В чат — 3-5 строк и ничего больше:

    T-XXX <название>
    Понял так: <как ты понял задачу, одна-две строки>
    Трогаю: <файлы и ассеты>
    Закончу: <что можно будет сделать в игре>

Апрува не жди. Понял не то — пользователь перехватит одной строкой.

## 8. Работай

Ход работы дописывай в файл задачи сразу, а не в конце. Дальше по CLAUDE.md:
дешёвая проверка, `review`, сценарий плейтеста.
