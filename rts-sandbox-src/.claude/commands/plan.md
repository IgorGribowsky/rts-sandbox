Загрузи скилл `dev-plan`.

## 1. Читай по ID, а не папкой

Видение, границы скоупа, список файлов в `docs/mechanics/` и открытые вопросы.
Состояние задач — одной командой: `node .claude/scripts/board.js --brief`.
`tasks/done/` не открывай.

## 2. Пересборка — это MERGE, а не генерация заново

Железные правила:
- **ID неизменяемы и не переиспользуются.** Номер даёт скрипт:
  `node .claude/scripts/board.js --next-id` (для подзадачи `--next-id T-012`).
- Статусы существующих задач не теряются и не сбрасываются.
- Закрытые версии и задачи из них не трогаются вообще.
- Задачу не удаляешь — переводишь в `cancelled` с причиной в `Итог`,
  либо в `backlog`, если просто отложена.

## 3. Что собираешь

Версии — файлы `milestones/vX.Y.Z.md` по `templates/milestone.md`.
Цель версии — 2-3 строки про состояние игры, не список задач.
Ровно одна версия со `status: current`.

**Порядок задач хранится ТОЛЬКО в поле `tasks` файла milestone.** В задаче
`milestone` — обратная ссылка. Подзадачи в этом списке не перечисляются:
принадлежность наследуется от родителя.

Задачи — по `templates/task.md`, формат в `templates/task-schema.md`.
Размер по смыслу; не влезает в один заход или не проверяется одним
плейтестом — разбивай на подзадачи (`parent`, ID суффиксом).

Механика в `proposed` или ответ не получен → задача создаётся, но с
`needs-design: true` и в работу не идёт. Находка не теряется, скоуп не растёт.

## 4. Покажи и дай править

В чат — версии и задачи списком, коротко. Пользователь правит свободным
текстом: «поменяй порядок», «T-008 не надо». Переписываешь и показываешь снова.

Первая сборка плана — предложи разбивку сам. Пользователь сказал, какие
версии хочет — его слово главнее твоей разбивки всегда.

## 5. Финал

    node .claude/scripts/board.js --validate

Исправь найденное, закоммить, скажи: доска обновилась, дальше `/next`.
