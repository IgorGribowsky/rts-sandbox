# T-031.1 · Захваченный рудник: балки в цвет команды

## Что нужно
Первый проход конвейера (`docs/08-model-pipeline.md`): Blender MCP
подключён, модель захваченного рудника размечена — балки получили
командный слот, при необходимости меш порезан, экспорт в проект. В Unity
красятся только командные слоты; модель без них не красится вообще.

## Как проверить
Захваченные рудники двух команд рядом: сам рудник одинаковый, балки — цвета
своей команды. Обычный рудник и прочие заглушки без разметки не красятся.

## План

- [x] Blender MCP прописан в проект (local scope, как в autorigPipeline);
  аддон `blender_mcp.py` в Blender 4.1 уже стоит. Нужен перезапуск сессии
- [x] `mine_held.fbx`: осмотр в Blender, балки → материал `TeamColor`
  (порезать меш, если граница не по граням), экспорт в `Assets/Models/`
  резать не пришлось: рама — уже отдельный объект `Cube`, купол — `Sphere`
  (материал `Mine`). Имена узлов сохранены — ID мешей в Unity те же
- [x] префаб `mine_held Body`: `Cube` → `TeamColor`, `Sphere` → `Mine` из FBX
- [x] `TeamMember`: красит только слоты с материалом `TeamColor`; нет слота —
  не красит
  окраска вынесена в `TeamMember.PaintTeamParts`, портрет на карточке
  (`UnitPreviewRenderer`) зовёт её же
- [x] проверка в Unity: захваченные рудники двух команд рядом, обычный рудник

## Итог

Рама захваченного рудника красится в цвет команды, купол — нет. Проверено в
Play: рудник команды 1 — рама `TeamColor (Instance)` (1,0,0), рудник команды
2, поставленный на время прогона, — (0,0,1); купол у обоих `Mine` (0.8 серый);
обычные рудники — `Default-Material`, не окрашены. Консоль чистая.
Цвет `TeamColor` в самой модели — пурпурный: так командные части видно в
редакторе, в игре его перекрывает цвет команды.
