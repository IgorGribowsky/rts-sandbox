# T-016.1 · Ассет способности — чистые данные, исполнение в обычных классах

## Что нужно
Первая из трёх подзадач T-016. Закрывает требования 1 и 2 из M-015.

Сейчас `SkillAction` — это `ScriptableObject` с методом `Act()`: ассет и
исполняемый код одно и то же. Надо развести. Ассет описывает «что за
способность» — числа, ссылки на префабы, набор импактов. Исполнитель —
обычный класс, который эти данные читает.

Схема та же, что уже принята для поведений в T-021: тип в enum, один
явный factory-switch, класс-исполнитель рядом. Новая способность — это
новый ассет; новый ВИД способности — новый класс плюс строка в фабрике.

Затрагивается: `Abstract/SkillAction.cs`, `ActiveSkillAction`,
`CastToPointAction`, `PassiveSkillAction`, три класса в `SkillActions/`,
`SkillImpact` и два импакта, `SkillParams`, вызов `Action.Act` в
`UnitSkills.Cast`.

## Как проверить
Кастер применяет все три способности: Light Orb, Water Wave, Blink.
Урон, дальность, скорость снаряда и дальность телепорта — прежние.

## План

### Главное решение: имена классов и полей не трогаю

Ассеты не переписываю вовсе. Классы данных остаются на месте с теми же
именами и теми же полями — из них уезжают только методы. Тогда ни `m_Script`,
ни `[SerializeReference]`-граф импактов внутри ассетов не меняются, и шесть
настроенных ассетов переживают задачу без единой правки. Это и есть самый
дешёвый способ не потерять числа.

Проверю это фактом: после работы `git status` по `SkillsSection/**.asset`
должен быть пустым.

### Что становится чем

```
было:  SkillAction : ScriptableObject   данные + Act()
стало: SkillAction : ScriptableObject   только данные + SkillActionType Type
       SkillActionExecutor              обычный класс, читает данные, исполняет
       SkillActionExecutorFactory       один явный switch по Type
```

То же самое для импактов: `SkillImpact` остаётся данными внутри ассета,
исполнение уезжает в `SkillImpactExecutor` со своей фабрикой.

Схема ровно та, что принята для поведений в T-021: тип в enum, один явный
factory-switch, класс-исполнитель рядом. Рефлексии нет.

### Файлы

Новые, в `SkillsSection/Scripts/Execution/`: `SkillActionExecutor`,
`CastToPointActionExecutor`, `ThrowProjectileExecutor`,
`ThrowWaveProjectileExecutor`, `InstantMovementToPointExecutor`,
`SkillActionExecutorFactory`, `SkillImpactExecutor`, `SkillUnitImpactExecutor`,
`InstantDamageExecutor`, `PoisonDamageExecutor`, `SkillImpactExecutorFactory`,
`SkillTargetFilter`. Новые enum-ы `SkillActionType` и `SkillImpactType`.

Правятся: `Abstract/{SkillAction, ActiveSkillAction, CastToPointAction,
PassiveSkillAction, SkillImpact, SkillUnitImpact}.cs`, три класса в
`SkillActions/`, два в `Impacts/`, `UnitSkills.Cast`.

`SkillTargetFilter` — это `CanHitCheck`, вынесенный из
`ThrowProjectileAction`; там же авторская пометка, что код просится в общий
хелпер.

### Чего в этой подзадаче НЕ делаю

- Навигационные свойства `SkillAction.Skill` и `SkillImpact.SkillAction`
  остаются. Прочитал код: их только пишут и нигде не читают, то есть они
  мертвы уже сейчас. Убирает их T-016.2 вместе с самой записью в ассет —
  это её содержание, не моё.
- Кулдаун и состояние в `UnitSkill` не трогаю — T-016.2.
- `SkillController` и клавиши не трогаю — T-016.3.
- Яд остаётся заглушкой: `PoisonDamageExecutor` продолжает бросать
  `NotImplementedException` с пометкой на T-001. Так решено в чате.

### Где живёт исполнитель

Создаётся на момент каста и не хранится нигде. Он не имеет состояния —
только ссылка на данные. Так в подзадаче не заводится ни одного нового
места, где что-то накапливается, а это как раз предмет T-016.2.

## Ход работы

- 2026-09-06 чекпоинт `12ed108`.
- Классы данных оставлены на месте с теми же именами и полями, из них убраны
  только методы. `SkillAction` и `SkillImpact` получили `Type` — тег, по
  которому фабрика выбирает исполнителя.
- Заведена папка `Execution/`: `SkillActionExecutor` и его дженерик-вариант,
  `CastToPointActionExecutor`, три исполнителя действий, `SkillImpactExecutor`,
  два исполнителя импактов, две фабрики и `SkillTargetFilter`.
- `CanHitCheck` вынесен из `ThrowProjectileAction` в `SkillTargetFilter` —
  ровно туда, куда просила авторская пометка в коде.
- `UnitSkills.Cast` больше не зовёт `Action.Act`, а строит исполнителя
  фабрикой.
- Unity перекомпилирован: ноль ошибок, ноль предупреждений.

### Проверка фактами

`git status` по `Assets/SkillsSection/**` не показывает ни одного изменённого
`.asset` — настроенные ассеты не тронуты вовсе. Значения, прочитанные уже
новыми классами:

```
ThrowLightOrb  [ThrowProjectileAction]      speed 20  range 13  Enemies  LightOrbProjectile
    impact InstantDamageImpact              damage 60  Magic
ThrowWaterWave [ThrowWaveProjectileAction]  speed 13  range 10  width 2.4  Enemies  WaveProjectile
    impact InstantDamageImpact              damage 40  Magic
Blink          [InstantMovementToPointAction] maxRange 8, импактов нет
LightOrb   cd 3.5  cast 0.15  range 12.5  mana 25  -> ThrowLightOrb
WaterWave  cd 7    cast 0.2   range 9.5   mana 55  -> ThrowWaterWave
Blink      cd 3    cast 0.15  range 50    mana 30  -> Blink
```

Совпадает со снимком, снятым до работы, до последнего числа. Ссылки на
префабы снарядов не пустые, импакты в `[SerializeReference]` не потеряны.

## Итог

Ассет способности стал чистыми данными: числа, ссылки и набор импактов.
Исполнение живёт в обычных классах за двумя фабриками — той же схемой, что
принята для поведений в T-021. Новый вид способности теперь добавляется
классом данных, классом-исполнителем и строкой в фабрике; новая способность
существующего вида — одним ассетом, без кода.
