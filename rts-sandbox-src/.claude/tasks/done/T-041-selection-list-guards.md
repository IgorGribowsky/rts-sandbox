# T-041 · Выделение разыменовывается без проверки на уничтоженность

## Что нужно
`UnitsController.SelectedUnits` — публичный список сырых `GameObject`, и
обращения к его элементам нигде не проверяют, жив ли объект: строки 59,
109, 169, 202, 223, 244, 266, 303, 348, 370, 443, 471, 573 (на 2026-09-07).
Любая новая дыра, из-за которой в список попадёт уничтоженный объект, снова
даст `MissingReferenceException` — и в другом месте, чем в прошлый раз.

Конкретную дыру закрыла T-040 (выделение больше не берёт того, кто уже
умер в этом кадре). Здесь речь о том, чтобы список сам держал инвариант:
в выделении только живые. Например, единая точка доступа, которая отсеивает
мёртвых, вместо тринадцати мест, где об этом надо помнить.

Заведено по ходу T-040 и сознательно НЕ сделано вместе с ней: фикс бага
должен был остаться минимальным и проверяемым.

## Как проверить
Обычная игра: выделение рамкой, двойным кликом, приказы, смерть юнита в
выделении — всё как раньше. Карточка и кольцо обновляются, когда юнит из
выделения умирает. Консоль чистая.

## План

- [x] `SelectedUnits` — свойство, отсеивает уничтоженные при каждом чтении
- [x] HUD узнаёт об отсеве в `LateUpdate`, не из геттера
- [x] Проверка в Play: уничтоженный объект в выделении, все приказы

## Ход работы

## Решения

- 2026-09-07 найдено при разборе T-040, заведено в бэклог с `origin: ai`.

- 2026-10-04 единая точка — геттер `SelectedUnits`: `RemoveAll(unit == null)`
  перед выдачей списка. Вызовы по 13 местам не трогал — все идут через
  геттер. Уведомление HUD не из геттера, а флагом в `LateUpdate`, чтобы не
  перестраивать интерфейс посреди чужого цикла. Поле перестало быть
  сериализуемым: в сцене остаётся пустой `SelectedUnits: []`, Unity его
  игнорирует.

## Итог

`UnitsController.SelectedUnits` теперь свойство и держит инвариант «только
живые». Проверено в Play: три юнита в выделении, один уничтожен в обход
события смерти — следующее чтение дало 2, приказы движения, A-move, hold,
сбор, проверка строителя и рамка прошли без исключений, консоль чистая.
