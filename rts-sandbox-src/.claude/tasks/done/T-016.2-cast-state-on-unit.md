# T-016.2 · Состояние каста живёт на юните, а не в ассете

## Что нужно
Вторая из трёх подзадач T-016. Закрывает требование 3 из M-015.

`UnitSkills.SetupNavigationProperties` в `Start` каждого юнита пишет ссылки
`Skill` и `SkillAction` прямо в общий ассет (`UnitSkills.cs:104-128`).
Каждый новый юнит переписывает их заново, а в редакторе запись остаётся
в ассете и после выхода из Play mode — это ровно тот случай из
`unity-asset-safety`, когда ScriptableObject меняется на диске молча.

Убрать запись в ассет совсем: навигационные ссылки не нужны, если
исполнитель получает данные параметром (T-016.1).

Заодно развести настройку и состояние боя. Сейчас `UnitSkill` внутри
публичного сериализуемого списка `Skills` держит и настройку (какой скилл,
какая клавиша), и текущий кулдаун. Кулдаун — состояние конкретного юнита,
в сериализуемом списке ему не место.

## Как проверить
Кастер кастует все три способности, кулдауны и мана считаются верно, два
кастера не мешают кулдаунам друг друга. После выхода из Play mode
`git status` показывает, что ни один ассет в `SkillsSection/` не изменился.

## План

Дерево чистое, отдельный чекпоинт-коммит не нужен: точка отката `534e5ce`.

### Настройка и состояние разъезжаются по двум классам

```
было:  UnitSkills.UnitSkill   Skill, Keycode  +  CurrentCooldown, Tick, StartCooldown
                              (сериализуется на префабе вместе с кулдауном)

стало: UnitSkills.SkillSlot   Skill, Keycode           — сериализуется, чистая настройка
       UnitSkills.UnitSkill   Slot, CurrentCooldown    — рантайм, на префабе не лежит
```

Имя `UnitSkill` остаётся за РАНТАЙМ-объектом намеренно: его тип ходит по
пяти файлам (аргументы событий каста, `SkillCastingToPointBehaviour`,
`UnitsController.prepearedSkill`, `UnitCommandManager`). Оставив имя, я не
трогаю ни один из них — меняется только `UnitSkills.cs`.

Сериализуемым становится новый `SkillSlot`. Это безопасно, и это проверено
фактом: в `Caster Unit.prefab` список лежит как

```
Skills:
- Skill: {fileID: 11400000, guid: 45f2a6f8..., type: 2}
  Keycode: 113
```

то есть Unity пишет только имена полей `Skills`, `Skill`, `Keycode`, а имя
вложенного класса в YAML не попадает вовсе. Все три имени я сохраняю, значит
настройка кастера (Q/W/E) переживает переименование. Проверю чтением с диска
после работы.

### Запись в ассет убирается совсем

`SetupNavigationProperties` удаляется. Вместе с ним — сами навигационные
свойства `SkillAction.Skill` и `SkillImpact.SkillAction`: прочитал код, их
только пишут и нигде не читают, а после T-016.1 исполнитель получает данные
конструктором и в них не нуждается.

### Файлы

Правится `UnitSkills.cs`, из `Abstract/SkillAction.cs` и
`Abstract/SkillImpact.cs` уходит по одному свойству. Больше ничего.

### Чего в этой подзадаче НЕ делаю

- Список запрещённых клавиш `banned` и `IsBanned()` остаются в `SkillSlot` —
  это проверка настройки, а не состояние боя. Сводит их в одно место T-016.3.
- `TryGetSkillCaster` и `prepearedSkill` в `UnitsController` не трогаю —
  T-016.3.
- Яд остаётся заглушкой — T-001.

### Что проверить фактами

- Список способностей на префабе кастера после работы: три слота,
  клавиши 113/119/101 (q/w/e), ссылки на LightOrb, WaterWave, Blink.
- После Play mode ни один `.asset` в `SkillsSection/` не изменён.

## Ход работы

- 2026-09-06 дерево чистое, точка отката `534e5ce`.
- `UnitSkills.UnitSkill` разделён надвое: `SkillSlot` — сериализуемая
  настройка (`Skill`, `Keycode`, проверка запрещённых клавиш), `UnitSkill` —
  рантайм-объект с кулдауном, который строится в `Awake` и на префабе не
  лежит. Имя `UnitSkill` оставлено за рантаймом, поэтому аргументы событий,
  `SkillCastingToPointBehaviour`, `UnitCommandManager` и `UnitsController`
  не тронуты вовсе.
- `SetupNavigationProperties` удалён. Вместе с ним убраны сами свойства
  `SkillAction.Skill` и `SkillImpact.SkillAction` — их только писали.
- `Cast` больше не достаёт `ManaCost` вторым приведением типа, берёт из уже
  полученного `activeSkill`.
- `BuildCastableSkills` пропускает пустые слоты: конфиг правит человек, и
  однажды там будет пустая строка.
- Unity перекомпилирован: ноль ошибок, ноль предупреждений.

### Проверка фактами

Настройка кастера пережила переименование сериализуемого класса. Префаб на
диске не изменился (`git status` его не показывает), в нём по-прежнему

```
Skills:
- Skill: {guid 45f2a6f8...}  Keycode: 113
- Skill: {guid b247c882...}  Keycode: 119
- Skill: {guid 2e536d2e...}  Keycode: 101
```

Прочитано через Unity уже новыми классами:

```
UnitSkills на префабе: есть, слотов 3
  Q -> Light Orb  (asset LightOrb)   banned=False
  W -> Water Wave (asset WaterWave)  banned=False
  E -> Blink      (asset Blink)      banned=False
```

Поиск по всему коду `SetupNavigationProperties`, `.SkillAction = `,
`Action.Skill = ` не находит ничего: писать в ассет способности больше
нечему. Что после Play mode ассеты действительно остаются нетронутыми —
это уже плейтест, отдельным пунктом в сценарии приёмки.

## Итог

(какой скилл на какой клавише) и состояние боя (кулдаун) живут в разных
классах — первое сериализуется на префабе, второе строится в `Awake` и
умирает вместе с юнитом.
