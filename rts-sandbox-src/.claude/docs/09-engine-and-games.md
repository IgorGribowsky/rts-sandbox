# Движок и игры на нём

Версия 0.5.0. Направление принято в чате 2026-10-04 (Q-19). Подробное
устройство — первая задача версии: дока процесса на утверждение, до
любого переноса кода.

## Что нужно (требования пользователя)

- Движок отдельно, игра на нём отдельно, обе — на Unity.
- Игре нужна новая механика — ИИ сам кладёт её в движок, чтобы её могли
  брать и другие игры. Пользователь в это не вмешивается.
- Правила, которые нужны только этой игре, в движок не идут. Если сказано
  «только для этой игры» или это очевидно — не идут. Неочевидно — ИИ
  спрашивает.
- В игре свои скрипты правил поверх общих скриптов движка.
- Игра стилизует интерфейс и прочее под себя, не трогая движок.
  Удобно, но с изоляцией.
- Изменение движка не ломает старые игры; переезд старой игры на новый
  движок — как можно проще.
- Тестовые сцены остаются в движке — на них пробуются механики.
- При разработке игры работают те же инструменты и скиллы пайплайна,
  плюс набор скиллов для работы с движком и игрой.
- Пользователь только общается с Claude: создание проекта игры и
  подключение движка делает ИИ.
- В версию входят: дока процесса, пользовательская инструкция «как делать
  игру на движке с ИИ» и тестовая игра, на которой показаны все
  возможности. Пайплайн разрешено адаптировать.

## Принятая схема

- **Движок — пакет Unity (UPM)** внутри проекта rts-sandbox. Тестовые
  сцены и полигон остаются в rts-sandbox.
- **Игра — отдельный Unity-проект** со своим репозиторием и своим
  `.claude/`. ИИ создаёт его сам: проект из командной строки Unity,
  манифест с движком и MCP for Unity, несущие настройки, копия пайплайна,
  `git init`. От пользователя — открыть Claude Code в папке игры.
- **Подключение:** игра в разработке берёт движок по локальному пути — его
  файлы редактируемы, правка механики в движке сразу видна в игре. Готовая
  игра привязана к git-тегу версии движка.
- **Одна линия движка.** Новая механика всегда ложится поверх последней
  версии. Игре на старом теге она нужна — игра сначала переезжает на
  последнюю версию по заметкам миграции. Патч от старой версии — только
  когда переезд дорогой, и только с вопроса пользователю.
- **Изменение движка и игры — два коммита**, каждый в свой репозиторий.
- У движка журнал версий с пометкой «ломает / не ломает» и заметками
  миграции, а также список своих игр, чтобы ломающее изменение было видно.

## Тестовая игра

«Выживание волн» (ответ в чате 2026-10-04): герой и казарма против волн
по таймеру, победа после N волн. Волны и победа — правила игры, в движок
не идут. Механика из концепта, которой нет в движке (воскрешение
существа после смерти с кулдауном 300 с), — идёт в движок.

## Открытые места

Решаются в доке процесса, первой задачей 0.5.0:

- граница «движок / игра» по существующему коду: что переезжает в пакет,
  что остаётся полигоном;
- как игра переопределяет стиль интерфейса и данные движка;
- как устроены доски задач двух проектов и связь между ними;
- имя пакета.
