# M-001 · Управление мышью и клавиатурой

## Зачем она в игре
Классическая RTS-раскладка: игрок водит рамкой, командует правой кнопкой и
переключает режимы буквами, не отрывая руку от мыши.

## Как работает
Весь ввод собран в одном `Update` (`WindowsInputController`), на старом
Input Manager. Клавиши — публичные поля, меняются в инспекторе.

Раскладка по умолчанию:

| Клавиша | Действие |
|---|---|
| ЛКМ | начать/закончить рамку выделения, подтвердить точку в режиме |
| ПКМ | контекстный приказ по цели под курсором, выход из режима |
| `A` + клик | атака по земле или юниту (A-move) |
| `H` | стоять на месте |
| `B` | открыть меню построек |
| `1`…`0` | производить юнита №N в выделенном здании |
| `Space` (удерживать) | камера на самый важный выделенный юнит |
| `F8` | зафиксировать камеру (перестать скроллить у краёв) |
| `Esc` | отмена: выход из режима, отмена приказа и стройки |
| `Shift` | добавить приказ в очередь вместо замены |

Режимы взаимоисключающие и проверяются в этом порядке: A-click, режим
постановки здания, меню построек, обычный режим. Каждый ранний режим
делает `return`, поэтому в режиме A-click остальные клавиши мертвы.

Клик — это `Physics.Raycast` на 100 юнитов дальности по маске из трёх слоёв:
`MovementSurface`, `Unit`, `HarvestedResource`. Постановка здания стреляет
только по `MovementSurface`.

Способности: любая клавиша, кроме занятых, на нажатии готовит скилл
(`PrepareSkillCast`), на отпускании кастует (`CommandSkillCast`) в точку под
курсором. То есть скилл срабатывает по отпусканию клавиши, а не по нажатию.

Отзывчивость (T-023): клавиша, зажатая раньше времени, не теряется. Пока
скилл нельзя скастовать — идёт кулдаун или не хватает маны, — ввод держит
такую клавишу в отдельном состоянии (`heldSkillKey`) и каждый кадр пробует
нажатие. В момент, когда скилл стал доступен, это считается НАЖАТИЕМ:
начинается каст и прицеливание. Сам каст, как и всегда, уходит по
отпусканию клавиши. Сбрасывается состояние отпусканием или `Esc`.

Смысл в том, чтобы игрок, поспешивший с нажатием, всё равно скастовал скилл,
а не в автоспуске: сам собой каст не уходит никогда.
Обе команды уходят в `SkillController`, а не в `UnitsController`.

Занятые клавиши перечислены в одном месте — `ReservedKeys` (T-016):

| Что | Клавиши |
|---|---|
| мышь | `Mouse0`, `Mouse1`, `Mouse2` |
| приказы и режимы | `A`, `H`, `B`, `S`, `Esc`, `Space`, `Shift`, `F8` |
| производство | `1`…`0` |

`S` занята заранее, под приказ «стоп» (T-032). `WindowsInputController`
берёт этот список за основу и добавляет к нему свои поля из инспектора,
поэтому переназначение клавиши там продолжает работать. `UnitSkills`
сверяется с тем же списком и сбрасывает запрещённую клавишу в `None`.

Позиция курсора: каждый кадр `UpdateMousePosition` бросает луч в землю,
округляет точку до шага `0.03 * GridCellSize` и, если округлённая точка
изменилась, шлёт `PlayerEventController.OnCursorMoved` с точкой и юнитом
под курсором. Округление нужно, чтобы событие не летело каждый кадр.

## Границы
Отвечает только за то, какая клавиша во что превращается. Что делать с
приказом — `UnitsController` (M-003) и `UnitCommandManager` (M-004),
со способностью — `SkillController` (M-015).
Скролл камеры считается здесь, но применяет его `CameraController` (M-002).

## Открытые места
- Переназначение клавиш игроком не предусмотрено — только инспектор.
- Пакет Input System в проект не подключён, используется legacy Input.
- Переназначив клавишу в инспекторе `WindowsInputController`, старую из
  занятых не выкинешь: список `ReservedKeys` статический, поля инспектора
  только добавляются к нему.
