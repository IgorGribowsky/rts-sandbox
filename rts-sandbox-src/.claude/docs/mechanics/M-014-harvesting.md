# M-014 · Рубка дерева и склад

## Зачем она в игре
Второй ресурс с другим ритмом: рабочий бегает туда-сюда, и игрок думает,
где ставить склад.

## Как работает
Дерево — префаб `Tree` с тегом `HarvestedResource`:
`IsHarvestedResource = 1`, `ResourceName = Wood`, `ResourcesAmount = 100`.

Рабочий должен иметь `IsHarvestor` и нужный ресурс в списке
`ResourcesCanBeHarvested` (у Builder там только Wood).

Числа рабочего (Builder): `HarvestingRate` 1 с на тик,
`HarvestingValuePerTick` 1 единица за тик, `HarvestingMaxValue` 10 — сколько
несёт за раз.

Цикл (`HarvestingBehaviour`):

1. ПКМ по дереву — юнит идёт к нему на `HarvestingDistance` = 0.3.
2. По прибытии начинает рубить: раз в `HarvestingRate` берёт
   `HarvestingValuePerTick` через `HarvestedResource.Take`.
3. Набрал `HarvestingMaxValue` — сам ищет склад и идёт туда.
4. У склада сдаёт всё в `PlayerResources` и возвращается к дереву.
5. Дерево кончилось (`ResourcesAmount <= 0`) — оно уничтожается, юнит
   ищет ближайшее другое с тем же `ResourceName`.

Автопоиск: дерево — в радиусе `ResourceFindDistance` = 35, склад — в
радиусе `StorageFindDistance` = 35. Склад ищется среди своих юнитов с
включённым `HarvestedResourcesStorage`.

Склад — любое здание с компонентом `HarvestedResourcesStorage` и нужным
ресурсом в списке `StoredResources`. Пока здание строится, компонент
выключен и складом не считается.

Ручная сдача: ПКМ по своему складу, когда рабочий уже что-то несёт, отправит
его сдавать не дожидаясь полной загрузки.

Если у юнита есть следующая команда в очереди, после сдачи на склад он не
возвращается к дереву, а идёт выполнять её.

## Границы
Золото добывается иначе, стоянием в шахте — M-013.

## Открытые места
- Ни дерево, ни рабочий не показывают, сколько несут: видно только в
  инспекторе (`CurrentResource`, `CurrentResourceValues`).
- Если складов нет в радиусе 35, задача просто завершается без сообщения.
- Дерево исчезает целиком, промежуточных стадий вырубки нет.
