# Модель → юнит с цветом команды

Замысел — `docs/08-model-pipeline.md`. Коротко: в цвет команды красятся
только грани с материалом **`TeamColor`**. `TeamMember.PaintTeamParts`
красит эти слоты и больше ничего; модель без такого слота не красится вообще.
Портрет на карточке (`UnitPreviewRenderer`) зовёт тот же метод.

Пользователь только просит в чате. Всё остальное делаешь ты, кроме одного
решения: **какие части командные**. Его предлагаешь ты, а утверждает
пользователь.

Проверено на двух случаях — держи их в голове как образцы:

| случай | что было | что сделали |
|---|---|---|
| `mine_held.fbx` (T-031.1) | готовый FBX, рама — отдельный объект | резать не пришлось: объекту назначен слот, перезаписали FBX поверх |
| казарма (T-031.2) | примитивный куб Unity (mesh `10202`) | куб собран в Blender, стены разрезаны по высоте, новый `Barracks.fbx` |
| все модели (T-031.3) | 6 FBX + 2 куба | у каждого исходника свои настройки экспорта — подбирались по факту в Unity (п. 6) |

## 1. Blender на связи

`get_addon_status`. Ответ «Could not connect to Blender» — Blender не открыт
или в аддоне не запущен сервер: попроси пользователя открыть Blender 4.1 и в
N-панели вьюпорта, вкладка BlenderMCP, нажать Connect / Start Server. Сам
Blender отсюда не запускается.

## 2. Отдельная сцена, чужое не трогать

У пользователя может быть открыто своё. Работай в новой сцене
(`bpy.data.scenes.new("<model>_work")`, `context.window.scene = ...`).

**Имена в `bpy.data` общие для всех сцен.** Стартовая сцена держит `Cube`
и `Material`: импорт объекта с именем `Cube` даст `Cube.001`, и Unity
получит другое имя узла (см. п. 6). Если имя занято — временно переименуй
чужой объект и его меш (`Cube__startup`), после экспорта верни. В конце
работы удали свою сцену и её объекты; Blender не сохраняй.

## 3. Осмотр

Для FBX из проекта: `import_scene.fbx`, затем по каждому объекту — имя
объекта и меша, число вершин и граней, слоты материалов, габариты, связность
(сколько кусков в меше). Снимок вьюпорта с `color_type = 'OBJECT'` или
`'MATERIAL'` — для тебя.

**Снимок вьюпорта (`get_viewport_screenshot`) может устареть**: если окно
Blender не перерисовывается, приходит прежняя картинка, и поворот вида или
объекта на ней не виден. Надёжно — рендер своей камерой в файл: временная
камера, `render.engine = 'BLENDER_WORKBENCH'`, `display.shading.color_type =
'MATERIAL'`, несколько азимутов, `render.render(write_still=True)` в
scratchpad, склейка в один лист PIL, чтение листа. Камеру потом удали.

Для тела на примитиве Unity (mesh `fileID 10202` куб, `10206` цилиндр,
`10207` сфера, `10208` капсула, `10209` плоскость): модель строишь сам той же
формы и размера — куб 1×1×1 с центром в нуле. Форма не меняется, меняется
только разбиение на грани.

Параллельно в Unity: префаб тела (`Assets/Prefabs/GameObjects/Units/Bodies/
<Name> Body.prefab`) — на каком объекте `MeshRenderer`, какой меш, какие
материалы. Тип юнита ссылается на префаб тела через `BodyPrefab`
(`Assets/Data/UnitTypes/`). Тело может состоять из нескольких дочерних
объектов, каждый со своим мешем из одного FBX (так у `mine_held`).

## 4. Предложение частей — в чат, и ждать ответа

2-3 варианта с ASCII-схемой, свой рекомендуемый первым. Командной части
должно быть заметно с игровой камеры (сверху и сбоку под углом), но не
вся модель — иначе возвращается «здание целиком в цвете команды». Что
обычно хорошо: пояс или знамёна на стенах, кайма, детали каркаса, плащ,
щит. Ответ — сразу в `Решения` задачи с датой и «ответ в чате».

Модель без командных частей по замыслу (рудник, дерево) не размечается.

## 5. Разметка

Материалы: командный — ровно `TeamColor`, цвет в Blender пурпурный
`(1, 0, 1)`, чтобы разметку было видно глазом; в игре его перекрывает цвет
команды. Остальное — один нейтральный материал с именем модели.

- **Часть — отдельный объект или кусок меша**: назначь слот граням, резать
  нечего.
- **Граница идёт поперёк граней**: режь. Для прямой границы —
  `bmesh.ops.bisect_plane` по всей геометрии (плоскость задаётся точкой и
  нормалью; в Blender вверх — Z), потом грани назначаются по центру
  (`calc_center_median`) и нормали. Для каймы на грани — `inset`.
  Плотность сетки поднимай только там, где проходит граница.
- Нейтральный — слот 0, `TeamColor` — слот 1. Но **порядок сабмешей в
  Unity не обязан совпасть со слотами**: Unity ставит материалы в порядке,
  в каком их встречают грани. У Builder вышло `TeamColor, Builder_base`.
  Порядок читай с узла FBX в Unity (п. 7), не выводи.

Ищи узлы шейдера по типу, не по имени (`n.type == 'BSDF_PRINCIPLED'`): имена
локализуются.

## 6. Экспорт

Префаб ссылается на меш FBX по **локальному ID, который Unity выводит из
имени**. Поэтому:

**Перезапись существующего FBX** (модель уже в проекте):
- имена объектов и мешей — ровно как были в исходнике (то, что Unity
  показывает как имена мешей). Каждую модель переименовывай перед своим
  экспортом и сразу возвращай: имена в `bpy.data` общие;
- **ДО экспорта** запиши отпечаток меша, как его видит Unity: центр,
  полуразмеры, число уникальных позиций вершин, сумма и сумма квадратов
  координат, `fileScale` импортёра. Сравнивается именно это — префаб берёт
  только меш, трансформ узла FBX ему не важен;
- **настройки экспорта у исходников разные**, обратный импорт в Blender
  этого не ловит (он совпадает при любых настройках). Сверка только в Unity.
  Уже подобранные:

  | исходник | настройки |
  |---|---|
  | `mine_held.fbx` | по умолчанию |
  | `WarriorCube`, `MageCube`, `farm`, `tower2` | `apply_scale_options='FBX_SCALE_UNITS'` |
  | `figure.fbx` | `FBX_SCALE_UNITS` + `bake_space_transform=True`, поворот объекта (Z 180°) запечён в меш, объект без поворота |
  | `Castle.fbx` | `FBX_SCALE_UNITS` + `scene.unit_settings.scale_length = 0.5` (у оригинала `fileScale` 0.5) |

  Признаки промаха: меш в 100 раз меньше, а масштаб 100 ушёл в узел — нужен
  `FBX_SCALE_UNITS`; оси переставлены — `bake_space_transform`; разница
  ровно в 180° — поворот объекта не запечён; разница в `fileScale` —
  единицы сцены;
- до совпадения отпечатка префабы не трогай; не сошлось и не ясно почему —
  `git checkout` файла, оригинал вернётся вместе с прежним импортом;
- пишешь поверх файла — `.meta` и GUID остаются, ссылки живы.

**Новый FBX** (модель на примитиве или новая): `apply_scale_options=
'FBX_SCALE_ALL'`, `bake_space_transform=True`. Тогда в Unity узел без
поворота и масштаба, меш в метрах, Y вверх — как примитив Unity. Имя файла
и объекта — по имени юнита (`Barracks.fbx`, объект `Barracks`).

Общее: `use_selection=True`, `object_types={'MESH'}`, `bake_anim=False`.

## 7. Unity: проверить импорт

`refresh_unity` (assets, force), потом чтение через `execute_code` (только
чтение!): по каждому мешу FBX — имя, локальный ID
(`AssetDatabase.TryGetGUIDAndLocalFileIdentifier`), число сабмешей, центр и
полуразмеры, у каждого сабмеша — диапазон по высоте; по узлам — трансформ и
материалы.

- Перезапись: имя и ID меша те же, отпечаток совпал (п. 6); в префабе ни
  одного пустого меша. Число вершин (не уникальных позиций) может чуть уйти
  — это сварка нормалей, не ошибка. Если резал меш, уникальных позиций
  станет больше — тогда сравнивай центр и полуразмеры.
- Порядок материалов на узле FBX (`MeshRenderer.sharedMaterials`) — это
  порядок сабмешей; по нему собираешь массив материалов префаба.
- Новый меш на месте примитива: центр и полуразмеры те же, что у примитива
  (куб — центр 0, полуразмеры 0.5). Иначе поплывут коллайдер, `ObstacleSize`
  и `UnitFactory.GetBodyExtents`.

## 8. Unity: префаб тела

Правка — `manage_prefabs` `modify_contents`, не кодом.

- Меш: `{"MeshFilter": {"m_Mesh": {"instanceID": <id меша>}}}`.
- Материалы — массивом целиком, по числу сабмешей:
  `{"MeshRenderer": {"m_Materials": [{"guid": "<нейтральный .mat>"},
  {"instanceID": <id TeamColor из FBX>}]}}`. Один элемент можно и
  `"m_Materials.Array.data[0]"`; `Array.size` инструмент не умеет.
- Нейтральный слот — тот материал, что стоял на префабе (вид не меняется).
  `TeamColor` — встроенный в FBX.
- Корень префаба инструмент ищет под именем ФАЙЛА: для корня `target` не
  задавай. **Инструмент переименовывает корень в имя файла** (`Barracks` →
  `Barracks Body`) — после правки верни `m_Name` текстом и проверь
  `git diff`: в нём должны быть только меш и материалы.
- Instance ID живут до перезагрузки домена — бери их прямо перед правкой.
- **Плейсеры** (`Assets/Prefabs/GameObjects/Units/Placers/`) держат копию
  меша и материалов тела для превью в редакторе. После правки тел —
  `refresh_unity`, затем меню `Tools/Units/Build Placer Prefabs`: он меняет
  только дочерний `Preview`, корень и `UnitPlacer` не трогает. Превью
  пересобирается у всех плейсеров с новыми fileID — у тех, чьё тело ты не
  менял, откати файл (`git checkout`), чтобы не было шума.
  Цвет команды на превью ставит сам `UnitPlacer.PaintPreview` по `TeamId`
  — ничего делать не нужно, слоты `TeamColor` он находит по имени.

## 9. Проверка

- Консоль после импорта и компиляции — без ошибок.
- Play. Первый вызов `execute_code` после входа в Play может вернуть пустой
  ответ — повтори. Поставь второй экземпляр другой команды:
  `UnitFactory.Create(type, pos, type.BodyPrefab.transform.rotation, teamId)`.
  **Высоту бери из префаба** (у зданий корень на `y = половина высоты`), на
  `y = 0` здание наполовину в земле, и снимок врёт.
  Много тел сразу — ряд по одному на команду, шаг по
  `UnitFactory.GetBodyExtents`.
- Прочитай `sharedMaterials` каждого рендерера: `TeamColor (Instance)` с
  цветом своей команды, остальные слоты — своим цветом у обеих команд.
- Снимок Game view (`manage_camera screenshot`, `view_position` /
  `view_target`, `output_folder: Temp/claude_captures` — не в `Assets`).
- В сценарий приёмки: где видно командную часть, что модель больше не
  перекрашивается целиком, карточка в меню.
