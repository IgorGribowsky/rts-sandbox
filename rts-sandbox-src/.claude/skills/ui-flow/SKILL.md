# Экраны, меню, HUD

Любой экран устроен одинаково: разметка, стиль, состояние, вход, выход.
Интерфейс ты делаешь не вслепую: после каждой видимой правки смотришь на
результат снимком (раздел 4).

## 1. Чем делаем

**UI Toolkit по умолчанию** — экраны, меню, HUD. Разметка в UXML, стиль в USS,
логика в C#. Всё текстом, диффится и правится пачкой.

- Один экран — один UXML и свой USS. Один общий `PanelSettings` на проект:
  масштабирование под размер экрана, эталонное разрешение, осознанный `Match`.
- Элементы достаёшь по имени один раз при открытии экрана и держишь в полях.
  Поиск элементов в каждом кадре — нет.
- **uGUI — только где UI Toolkit не справляется**: интерфейс внутри 3D-мира
  над объектами, если в версии Unity проекта UI Toolkit этого не умеет;
  анимация через Animator; готовый пакет, который требует Canvas. Выбрал
  uGUI — скажи одной строкой почему.
- Проект уже на uGUI — старые экраны не переделываешь без задачи на это,
  новые делаешь на UI Toolkit. Смешивать можно.
- WebGL — тоже UI Toolkit. HTML и CSS страницы — только то, что вокруг canvas
  (страница, загрузка), не интерфейс игры: в редакторе его нет.

## 2. Стиль: тема и дока

**Все значения стиля — только в переменных USS** темы:
`Assets/_Project/UI/Theme/theme.uss` — цвета, шрифты, размеры текста,
отступы, радиусы, длительности переходов. Экранные USS ссылаются на
переменные через `var(--...)`, своих чисел цвета и размера не заводят.
Поменял стиль — правишь переменную, и меняются все экраны сразу.

**`docs/ui-style.md` ведёшь сам**, это твоя рабочая дока, без статуса и без
апрува. Заводишь на первой задаче с интерфейсом. Внутри только замысел:

- настроение и характер интерфейса в 2-3 строки;
- на какие референсы опираемся — имена файлов из `references/`;
- правила: иерархия, где акцентный цвет, как выглядят кнопки и панели,
  что запрещено.

Чисел в доке нет — они в теме, иначе разъедутся. Правишь доку — сверяешь
тему и экраны с ней в той же задаче. Меняешь общий характер стиля, а не
деталь — скажи пользователю одной строкой.

**Шрифт не дефолтный.** Своего шрифта в проекте нет — `handoff` на шрифт
(`kind: шрифт`), до тех пор дефолтный как заглушка.

## 3. Референсы

Пользователь сослался на картинку из `references/` — в задаче, в идее или
в чате — открываешь её и записываешь имя в `ui-style.md`. Дальше по задачам
интерфейса эти файлы открывать можно без новой ссылки. Остальное в
`references/` не открываешь. Картинки дорогие: открывай ту, что нужна
для текущего экрана, а не все.

## 4. Снимок — твоя проверка

После каждой видимой правки интерфейса:

1. Приведи игру в состояние, где экран виден. `UIDocument` рисуется в
   Game view и без Play mode; нужна логика открытия — Play mode.
2. Сними Game view инструментом MCP — имя возьми из живой схемы сессии.
   Около 1280×720, больше не нужно: снимок стоит ~1-1.5 тыс. токенов.
3. Сверь с референсом и `ui-style.md`: выравнивание, обрезанный и
   вылезающий текст, контраст, одинаковые отступы, ничего не прилипло к краю.
4. Правь и снимай снова — не больше трёх кругов на одну правку. Не сошлось
   за три — `review` и в чат, что именно не получилось.

- На задачах, где меняется раскладка экрана, — один снимок ещё и в другом
  соотношении сторон.
- Снимки для тебя. Пользователю не показываешь и не описываешь их в чате.
- Снимок не остаётся в `Assets/`: инструмент кладёт его туда — удали вместе
  с `.meta` сразу после просмотра.
- Инструмента снимка в схеме MCP нет — скажи об этом и проверяй фактами
  элементов. «Проверил визуально» без снимка не пишешь.

## 5. Состояния и переходы

- Экран сам себя не открывает. Открывает и закрывает тот, кто управляет
  состоянием игры. Состояния (титул, игра, пауза, смерть) и переходы между
  ними — в одном месте: иначе пауза откроется поверх экрана смерти.
- HUD — не экран: живёт всё время игры, показывает и прячет элементы.
- Пауза через игровое время, но анимации и звук меню от него не зависят.
  Выход из паузы возвращает прошлое значение времени, а не единицу.
- Рестарт: явно решить, перезагружается сцена или сбрасывается состояние.

## 6. Ввод, фокус, навигация

- При открытии экрана фокус ставится на элемент явно — иначе с клавиатуры
  и контроллера экран мёртвый.
- Возврат назад работает на каждом экране, не только кнопкой на нём.
- Указатель и навигация не дерутся за фокус: подсветка за последним
  использованным устройством.
- Карты ввода переключаются при входе в меню и выходе — иначе «мистический
  выстрел» при навигации по меню.

## 7. HUD обновляется событиями

- Значение изменилось → владелец значения сообщает, HUD перерисовывает
  только изменившееся. Опроса в каждом кадре нет.
- Подписался — отпишись при выключении, иначе после рестарта двойные
  обновления и ссылки на мёртвые объекты.
- Числа, которые скачут каждый кадр, сглаживает сам элемент.

## 8. Тексты

Строки не хардкодишь в UXML и коде: держишь в одном месте, даже если
локализации не планируется.

## Чем проверить фактами

- Снимок совпадает с референсом и докой стиля (раздел 4).
- Открыт ровно один экран, фокус на конкретном элементе — прочитай.
- Экранные USS не содержат своих значений цвета и размера — только `var(--...)`.
- Консоль чистая после перекомпиляции.
- Ощущение от интерфейса — плейтест: в сценарий приёмки что открыть, что
  нажать, на что посмотреть.
